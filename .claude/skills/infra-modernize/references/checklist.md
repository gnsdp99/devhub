## Dockerfile

**베이스 이미지 태그** — 태그가 존재하는지, 유지보수 중인지. `latest`나 메이저만 붙은 태그는 재현성이 없다. 반대로 너무 세밀하게 고정하면 보안 패치를 놓친다.

**멀티스테이지 분리** — 빌드 도구가 런타임 이미지에 남아 있으면 공격 표면이 넓어진다. 컴파일러·패키지 매니저·소스가 최종 이미지에 없어야 한다.

**레이어 순서** — 변경 빈도가 낮은 것부터 높은 것 순으로 `COPY`한다. 의존성 설치와 애플리케이션 코드 복사가 한 레이어에 섞이면 캐시가 매번 무효화되고, 배포마다 전체 크기가 전송된다. Java라면 Spring Boot layered 추출로 의존성과 애플리케이션을 갈라 배포 전송량을 크게 줄일 수 있다.

**비루트 실행** — `USER`가 없으면 root로 돈다. UID와 GID를 모두 명시해 만들고 `USER`는 숫자로 쓴다. 숫자여야 쿠버네티스의 `runAsNonRoot` 검증을 통과하고, passwd 엔트리가 있어야 홈 디렉터리를 쓰는 라이브러리가 깨지지 않는다.

**HEALTHCHECK** — 정의 위치가 이미지인지 compose인지. 이미지에 두면 어디서 띄우든 따라간다. 셸 형식(`CMD-SHELL`)은 `/bin/sh`로 실행되므로 bash 확장을 쓰면 실패한다. 이미지에 `curl`이 없는 경우도 흔하다.

**크로스 컴파일** — 다른 아키텍처를 대상으로 빌드한다면 빌드 스테이지에 `--platform=$BUILDPLATFORM`을 붙여 네이티브로 돌린다. 인터프리터·바이트코드 산출물은 아키텍처 중립이라 에뮬레이션할 이유가 없다. 최종 스테이지의 `RUN`만 에뮬레이션되며, 이것도 없앨 수 있으면 QEMU 자체가 불필요해진다.

**비밀값** — `ARG`나 `ENV`로 들어온 값은 이미지 히스토리에 남는다. 빌드 시 비밀이 필요하면 `--mount=type=secret`을 쓴다.

**`.dockerignore`** — 없으면 빌드 컨텍스트에 `.git`, `node_modules`, 로컬 `.env`가 통째로 실린다. 느려지는 것보다 비밀값 유출이 문제다.

## Compose 파일

**`version:` 키** — Compose 스펙에서 제거됐다. 남아 있으면 경고가 뜬다.

**리소스 제한** — 스펙 표준은 `deploy.resources.limits`다. `mem_limit`·`cpus`는 레거시다. "`deploy`는 swarm 전용이라 무시된다"는 안내가 널리 퍼져 있지만 현행 Compose에서는 적용된다 — 판단이 갈리면 두 방식을 나란히 띄워 `docker inspect -f '{{.HostConfig.Memory}}'`로 확인한다.

**환경변수 중계** — 애플리케이션이 환경변수를 직접 읽고 기본값도 갖고 있다면, compose가 `.env` → compose 변수 → 컨테이너 환경변수로 한 번 더 중계할 이유가 없다. `env_file` 한 줄로 줄어드는 경우가 많다. 다만 컨테이너 네트워크 안에서만 유효한 값(서비스 이름이 들어간 접속 URL 등)은 중계가 아니라 변환이므로 남긴다.

**포트 바인딩** — `"8080:8080"`은 모든 인터페이스에 노출된다. 리버스 프록시 뒤에 둔다면 `"127.0.0.1:8080:8080"`으로 묶어야 프록시 우회를 막는다.

**의존 순서** — `depends_on`만으로는 컨테이너 시작만 기다린다. 실제 준비 상태를 기다리려면 `condition: service_healthy`가 필요하다.

**재시작 정책과 실패 처리** — `restart` 정책이 의미를 가지려면 프로세스가 실제로 죽어야 한다. 메모리 고갈 시 살아 있는 척하는 런타임(JVM 등)은 즉시 종료하도록 설정해야 재시작과 헬스체크가 작동한다.

**운영 파일과 개발 파일 분리** — 운영 compose에 개발용 DB 서비스가 남아 있는지, 두 파일이 같은 설정을 복제하고 있는지.

## GitHub Actions

**액션 버전** — 전부 조회한다. 메이저가 여러 단계 뒤처진 경우가 흔하다. 참고로 `gradle/actions/setup-gradle`은 v4부터 Gradle Wrapper 검증을 내장하므로 별도 `wrapper-validation` 액션이 중복이다.

**자격증명 방식** — 클라우드 접근에 장기 액세스 키를 시크릿으로 넣고 있다면 OIDC로 바꾼다. 신뢰 정책은 저장소와 브랜치까지 좁힌다.

**권한 경계** — `pull_request` 이벤트는 PR 브랜치에 있는 워크플로 파일을 실행한다. 따라서 CI 워크플로에 `id-token: write`나 배포 권한이 붙어 있으면, PR에서 워크플로를 수정해 그 권한을 쓸 수 있다. 배포는 `push`나 `workflow_run`으로 트리거되는 별도 워크플로에 격리한다. `workflow_run`으로 트리거된 워크플로는 언제나 기본 브랜치 버전이 실행되므로 이 경로가 구조적으로 막힌다.

**`permissions` 명시** — 워크플로나 잡 수준에 선언이 없으면 저장소 기본값을 그대로 받는다. 필요한 것만 준다.

**트리거 조건** — `workflow_run`을 쓴다면 `conclusion == 'success'`, `event == 'push'`, `head_branch` 세 조건을 함께 건다. 하나라도 빠지면 의도치 않은 배포가 발생한다.

**중복 빌드** — 같은 커밋을 CI와 CD가 각각 빌드하고 있는지. 아티팩트를 넘기거나 조건을 좁혀 없앨 수 있는 경우가 많다. 다만 main 푸시 시의 검증 실행은 중복이 아니다 — PR이 검사한 것은 가상 머지 커밋이고, 그 사이 다른 PR이 머지됐다면 실제 커밋은 다르다.

**캐시 전략** — 캐시 백엔드의 용량 제한과 스코프 규칙을 확인한다. 쓰기를 PR마다 하면 한도를 잠식하면서 서로 재사용도 안 된다. 기본 브랜치에서만 쓰고 PR은 읽기만 하는 구성이 보통 맞다.

**아티팩트 캐시 제어** — 정적 사이트를 배포한다면 해시가 붙은 자산과 이름이 고정인 진입 파일의 캐시 정책이 달라야 한다. 그리고 자산을 먼저 올리고 진입 파일을 마지막에 올려야 배포 중 없는 파일을 가리키는 창이 생기지 않는다.

**공급망 증명** — 이미지 빌드라면 provenance와 SBOM 첨부를 켤 수 있다.

## 배포 셸 스크립트 / cloud-init

**셸 방언** — `#!/bin/sh`인데 bash 문법을 쓰고 있는지. `set -euo pipefail`의 `pipefail`도 dash에 없다.

**패키지 설치 경로** — 시스템 파이썬에 `pip install`을 하고 있다면 최근 배포판에서 PEP 668로 거부된다. venv나 pipx가 권장 경로다. 배포판 이미지에서 직접 확인할 수 있다.

**다운로드 URL의 버전과 아키텍처** — 핀한 태그가 존재하는지, `$(uname -m)`으로 조립한 자산 이름이 대상 아키텍처에서도 200인지.

**비밀값 취급** — 스크립트에 토큰이 하드코딩돼 있는지, 파라미터 스토어에서 읽더라도 `umask`와 파일 권한이 적절한지, 로그에 찍히지 않는지.

**멱등성** — 부트스트랩 스크립트를 두 번 돌리면 깨지는지. 재실행이 안전해야 복구가 쉽다.

**갱신 자동화** — 인증서처럼 만료되는 것에 갱신 타이머가 걸려 있는지, 갱신 후 서비스 리로드 훅이 있는지.

## AWS 리소스 설계

**생성 시점에만 켤 수 있는 기본값** — IMDSv2 강제, EBS·RDS 저장 암호화가 대표적이다. 나중에 바꾸려면 재생성해야 하므로 처음부터 지정한다. IMDSv2를 강제하지 않으면 SSRF 하나로 인스턴스 자격증명이 유출될 수 있다.

**컨테이너 레지스트리 태그** — 가변 태그(`latest`)와 태그 불변성은 양립하지 않는다. 배포를 커밋 SHA로 한다면 가변 태그는 추적을 흐릴 뿐이다. 라이프사이클 정책으로 오래된 이미지를 정리한다.

**네트워크 비용** — 프라이빗 서브넷에 아웃바운드가 필요한 리소스를 두면 NAT Gateway가 붙는다. 고정비가 크므로 정말 필요한지 확인한다. 보안 그룹으로 인바운드를 막고 퍼블릭 서브넷에 두는 선택이 나은 경우가 있다.

**퍼블릭 IPv4** — 사용 중이어도 과금된다. 개수를 확인한다.

**오리진 보호** — CDN 뒤의 오리진이 직접 접근 가능한 상태인지. 관리형 prefix list로 CDN 대역만 허용하면 우회를 막을 수 있다.

**전송 구간 암호화와 보안 헤더** — CDN이라면 관리형 보안 헤더 정책으로 HSTS 등을 오리진 수정 없이 붙일 수 있다.

**접속 경로** — SSH 포트를 열어두고 키를 CI 시크릿에 넣는 대신 세션 관리자 계열을 쓰면 포트도 키도 없앨 수 있고 접속 로그가 감사 추적에 남는다.

## 인프라 설계 문서

문서는 코드와 다른 방식으로 낡는다. **설정 파일을 고쳤으면 문서의 해당 서술도 함께 고친다.** 문서가 이전 결정을 그대로 기술하고 있으면 다음 사람이 문서를 믿고 되돌린다.

특히 확인할 것 — 인스턴스 타입·이미지 아키텍처 같은 구체 사양, 비용 추정치의 기준일, 다이어그램의 구성요소, "왜 이렇게 했는가"가 최신 판단을 반영하는지.

비용 수치를 적을 때는 조회 기준일을 함께 적는다. 단가는 바뀌고, 기준일이 없으면 언제 틀린 값이 됐는지 알 수 없다.
